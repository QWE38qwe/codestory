# CodeStory 项目运行说明

## 环境

- Node.js 22.12 或更高版本，npm 10 或更高版本。
- SQLite 数据库由 Fastify Server 使用 Prisma 管理。
- 本地单用户部署；Web 与 API 开发时分别运行，生产由 Fastify 同源托管。

## 首次启动

```powershell
npm install
Copy-Item .env.example .env
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

将上条命令生成的值填入 `.env` 的 `CODESTORY_CREDENTIAL_KEY`。这是本地凭据加密主密钥，不要提交 `.env`。然后生成 Prisma Client 并启动；启动命令会通过 `db:init` 自动执行尚未应用的 migration：

```powershell
npm run db:generate --workspace @codestory/server
npm run dev
```

默认 Web 地址为 `http://127.0.0.1:5173`，API 地址为 `http://127.0.0.1:3000`。结束开发服务时按 `Ctrl+C`。

## 使用仓库分析

1. 在顶部点击“解读仓库”。
2. 填写公网 HTTPS 的 OpenAI-compatible 模型地址、模型名称和 API Key。服务端先测试连接，成功后以 AES-256-GCM 加密保存；页面只展示末四位掩码。
3. 选择 GitHub 或本地文件夹。私有 GitHub 仓库可在服务端 `.env` 配置 `GITHUB_TOKEN`。
4. 点击“自动分析并生成 Story”。服务端创建异步 Job，前端展示进度并在完成后打开 Story Player。

本地文件限制为最多 400 个上传文件、单文件不超过 200 KiB、总计不超过 25 MiB。服务端过滤依赖目录、构建产物、锁文件和不支持的扩展名。源码只在 Job 临时工作区中保存，Job 完成或失败后删除；服务启动时会清理超过 24 小时的孤儿目录。

## 构建与测试

```powershell
npm run build
npm test
npm run test:e2e
```

`npm start` 以生产模式启动 Fastify；执行前需完成构建、配置 `.env` 并初始化 SQLite。生产服务器同源返回 `apps/web/dist` 页面与 `/api`。

## 支持范围与边界

- GitHub `github.com` 仓库及受限本地文件夹。
- JavaScript、TypeScript、Python 源码；Markdown 和 JSON 作为上下文读取。仓库过大时需指定较小子目录，服务端最多分析 90 个高相关文件。
- 每个 Job 自动选择最多 3 个能对应到真实文件的 Feature 并生成 Story。没有 SOURCE 证据的 Action 不会保存。
- 单进程、单并发分析，不包含用户账号、多实例、Docker 或公网部署。
- 两个预置 Demo 始终保留，可离线播放，不依赖 Server、数据库或模型。
